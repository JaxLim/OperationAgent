# ADR-PLAT-001：Agent 平台能力（规划与编排、目标驱动、技能与插件、上下文与性能、可靠性）

状态：**范围已由用户指令授权；A 类决策可按本 ADR 实施，B 类决策提议中（逐项批准前保持关闭）**。日期：2026-11-10。提出方：AI 编程助手，受用户 2026-11-10 指令委托（原话记录于 `build/agent-status.json` 的 `platform.authorization`，由 `pnpm verify:agent` 校验）。

本 ADR **不修改** `ARCHITECTURE.md` / `AGENTS.md`（两者仍按 `0.4.0-p0` 哈希冻结），不改变 ARCHITECTURE §2.2 的任何边界不变量，也不提前开放任何未通过门禁的能力。它做三件事：把 §1.2 / §15.3 中列为“非目标 / DEFERRED”的若干能力按 §16 的要求先立 ADR 再分阶段解除暂缓；确定这些能力在现有进程与信任边界内的落点；区分哪些决策只是在既有边界内增加能力（A 类），哪些会改变边界（B 类，必须由用户对具体决策另行批准）。

## 1. 背景与现状

用户指令要求把 OperationAgent 建成可独立完成复杂任务的自主 Agent 平台，优先级依次为：规划与编排、目标驱动的自主工作流、技能与插件生态、性能与 Token 效率、生产可靠性；并明确要求“自主执行仍须受适当的用户审批和安全边界约束”。

截至本 ADR：

- 已有：Electron Main / Preload / Renderer / Express / 隔离 Worker 的完整进程链；SQLite 事件存储与任务状态机；Model Gateway（Claude Messages API，流式、自适应思考、拒答回退、提示缓存）；Read Adapter 与两个只读工具（`read_file`、`list_directory`，仅 Windows x64）；Agent Loop（Worker 驱动、Express 持有会话并执行工具）；对话界面；Windows x64 上 SEC-W01 与隔离运行时端到端测试在一次性 runner 通过。
- 没有：任务内计划、跨任务的会话与目标、检查点与恢复、技能、MCP Host、子 Agent、写入与 Shell（M3）、上下文管理（会话只增不减，超过窗口即失败）、任何性能度量。
- 冻结规范中与本 ADR 相关的条目：§1.2 把 Multi-Agent 编排、长期语义记忆、复杂自动检查点恢复、插件市场列为 V1 非目标；§15.3 把多 Agent 编排、长期记忆、完整上下文压缩系统、插件市场列为 DEFERRED；§5.4 规定“首版不建设插件市场、脚本运行市场或热插件生命周期系统”；§16 要求对暂缓事项“先修改 ADR 并增加测试”。

## 2. 不变的约束

以下约束对本 ADR 的所有决策生效，任何实现不得以“平台能力需要”为由放宽：

1. Express 是唯一授权入口；Worker 不持有会话内容、凭据、文件或网络能力，只驱动循环（§2.2-1/4，§6.1）。
2. 工具能力只来自 Express 的静态 Tool Registry 与用户授权。模型输出、技能正文、插件清单、MCP 工具描述都是**数据**，不能增加工具、扩大路径范围或改变审批等级（§5.4，§6.1）。
3. 工作区文件只经 Read Adapter 短命子进程读取；Express、Main、Renderer 进程内不执行第三方代码，不直接读取工作区文件（§5.2，AGENTS §5）。
4. 各平台能力独立门禁、Fail-Closed；新的只读操作在某平台通过 SEC-08 之前不在该平台开放（§5.3）。
5. 事件日志只存元数据；工具结果（文件正文）不落盘（M2 第五切片的既定做法，本 ADR 保持）。
6. 任务不自动重放；中断后的继续必须由用户明确选择（§8.3，ADR-005）。

## 3. 从领先系统得到的设计原则

评估了 Claude Code、OpenAI Codex CLI 等系统的公开做法与当前 Claude API 的行为，对本项目有约束力的结论如下：

- **会话只追加。** 当前 Claude 模型把思考块绑定到产生它的会话前缀：编辑、重排或删除较早的回合（包括客户端删除旧工具结果）会使其后的思考块失效，新账号上直接返回 400；提示缓存同样按前缀命中。因此上下文管理不能靠改写历史实现，只能用服务端的上下文编辑与压缩（不算编辑），或在安全边界处做“只带摘要重新开始”的整体压缩；系统提示与工具集合在一次会话内冻结，中途的操作指令以追加的 `role: "system"` 消息表达。
- **计划是状态，不是文字。** 计划由模型通过一个无副作用的工具提交，控制面校验、持久化并展示；进度、停滞检测和完成核对都基于这份状态，而不是解析模型的自然语言。
- **渐进披露。** 技能与大量工具只把名称和一句描述放进上下文，正文与 Schema 按需加载；固定上下文保持很小且稳定，缓存前缀不被破坏。
- **检查点等于持久化的摘要。** 可恢复执行不需要保存完整会话（也不应保存文件正文）：在回合边界保存“计划 + 模型写的进度摘要 + 已确认事实”，恢复时以它开启一段新会话。这与整体压缩是同一种形状，一套机制同时服务于长任务、恢复和后续追问。
- **子 Agent 用于隔离上下文，而不是并行本身。** 读得多、结论短的子任务交给独立会话，只把结论带回主会话；主会话保持同一模型以保住缓存。
- **先度量再优化。** 每个回合记录首字延迟、耗时、各类 Token 与缓存命中；离线基准只声明它能确定测量的量，需要真实 API 的结论单独验证并如实标注。

## 4. 决策

### A 类：在既有边界内增加能力（范围已授权，可实施）

**D1 上下文引擎。** 落点：Express Model Gateway 与 `Conversation`。
- 请求启用服务端工具结果清理（`clear_tool_uses_20250919`）与服务端压缩（`compact_20260112`），阈值为契约中的固定策略常量；响应中的压缩块作为会话内容原样保留并回传。
- 会话保持只追加；新增自动化检查：连续请求的 `system`、`tools` 与 `messages` 公共前缀逐字节一致。
- 这些是 beta 能力且无法在本仓库 CI 中对真实 API 验证：若启用后某回合返回 `invalid_request`，该任务关闭上下文管理并重试该回合一次，事件中记录降级；不重试两次，不影响未启用时的行为。
- 压缩摘要只存在于 Express 内存中的会话里，不落盘。

**D2 度量与基准。** 每个模型回合记录首字延迟与耗时，每次工具调用记录耗时；任务快照汇总输入 / 输出 / 缓存读写 Token 与缓存命中率（均为元数据）。新增离线基准命令，测量网关自身开销、Read Adapter 每次调用耗时、请求体随回合的增长与前缀稳定性；结果写入 `docs/benchmarks/`。涉及真实 API 花费的基准需用户提供密钥并同意后单独运行。

**D3 选择性检索。** `read_file` 支持行范围；新增 `search_text`（工作区内文本搜索）与 `find_files`（按名称模式查找）。全部在 Read Adapter 子进程内实现，沿用同一套路径策略、敏感路径拒绝、身份复验、输出与时间上限；每个新操作补齐 SEC-08 同类测试，未通过的平台不登记。

**D4 计划与进度。** 新增控制面工具 `update_plan`（通道 `control-plane`，能力 `plan`，不接触文件、进程或网络）：模型提交步骤列表（标题、状态、可选依赖），Express 校验后写入事件并更新任务快照，界面显示。任务结束时若仍有未完成步骤，如实标注而不是静默算作完成；连续多回合没有计划进展时追加一条系统消息提醒（只追加，不改历史）。

**D5 会话与检查点。** 任务归属于会话；同一会话的后续提问沿用仍在内存中的会话（缓存仍热），否则从最近的检查点开始。检查点内容为计划、模型写的进度摘要和用量统计，写入 SQLite；它与已落盘的回答同属“模型文本”，可能引用文件内容，因此提供设置项可关闭检查点持久化（关闭后不能跨重启继续）。被中断任务的继续仍需用户明确选择，并从检查点开始一段新会话，不重放旧会话。

**D6 技能（只读）。** 技能是含 `SKILL.md` 的目录（YAML frontmatter 至少含 `name`、`description`，与通行的 Agent Skills 格式兼容）。来源限于当前项目内的 `.operationagent/skills/`（并兼容读取 `.claude/skills/`、`.agents/skills/`）。按项目逐个启用，记录正文哈希，内容变化后需重新启用。任务开始时把已启用技能的名称与描述固定进系统提示（有数量与长度上限），正文由 `load_skill` 工具经 Read Adapter 按需读取。技能不能声明或获得工具能力；技能附带的脚本在 M3 沙箱可用之前不可执行。

### B 类：改变边界，需要用户对具体决策另行批准

**D7 多 Agent 编排。** 提议：子 Agent 是 Express 中的子会话（独立系统提示、工具集合为父任务的子集、可选更便宜的模型），其循环与父任务在同一个隔离 Worker 内并发运行（上限 4），结论以有界文本作为工具结果返回父会话；首期不允许嵌套。这改变“Worker 同一时间只运行一个任务”的运行模型并新增 RPC 能力（协议协商，不改帧格式），需要批准后实施，并补充并发循环的隔离、取消与配额测试。

**D8 目标驱动运行。** 提议：目标是带验收条件与预算（回合、Token、时间）的持久对象，可跨多个任务段自动推进：调研 → 计划 → 执行 → 核验 → 反思；每段在预算内自动续接，超出已授予能力的操作仍逐项审批。自动续接意味着“无人值守地开始新的模型回合”，属于自主程度的变化，需要批准具体的默认预算与停止条件后实施。

**D9 MCP Host 与插件。** 提议：插件是清单 + 技能 + MCP Server 定义 + Agent 配置的包，不含在 Main / Renderer / Express 内执行的代码；本地 stdio MCP Server 只在通过本平台 P3b 的工具沙箱内运行，远程 MCP 走按 Server 白名单的 HTTPS 与独立凭据；工具名带命名空间，审批策略按工具登记；生命周期为安装（校验清单与哈希）→ 启用（逐能力授权）→ 更新（哈希变化需重新授权）→ 停用。这部分解除 §5.4 的“不建设插件生命周期系统”，并依赖 M3，需批准后实施。

**D10 工作区之外的技能目录。** 用户级技能目录位于工作区之外，需要为 Read Adapter 增加第二个授权根，属于读取范围的变化，需批准后实施。

写入与 Shell（M3）、签名与更新（M4）已在既有授权内，按 ARCHITECTURE §5 / §13 执行，不由本 ADR 改动。

## 6. 后果与风险

- 上下文管理依赖两个 beta 能力。缓解：固定策略、可观测的降级路径、自动化的前缀检查；真实 API 行为在取得密钥与同意后单独验证，在此之前文档只声明离线可验证的部分。
- 新的只读操作扩大了 Read Adapter 子进程的代码量。缓解：逐操作 SEC-08 测试与平台登记，未通过即 `READ_ADAPTER_UNAVAILABLE`。
- 检查点把模型写的摘要落盘。缓解：与回答同等对待、有大小上限、可关闭；工具结果仍不落盘。
- 项目内的技能是不可信内容，可能包含提示注入。缓解：逐项目启用并绑定哈希；技能不能扩大能力；正文以工具结果（数据）而非系统提示进入会话。
- B 类决策未批准时，对应里程碑在状态文件中只能是 `not-started` 或 `blocked`，由 `pnpm verify:agent` 强制。

## 7. 回滚

A 类能力各自有独立开关点：上下文管理可通过策略常量整体关闭（请求恢复为 M2 的形状）；新工具可从 Tool Registry 的平台登记中移除；检查点可由设置关闭。迁移只增不改，回滚代码不需要回滚数据库。

## 8. 待用户批准的事项

1. **D7** 子 Agent 在同一隔离 Worker 内并发运行（上限 4、不嵌套）。
2. **D8** 目标驱动运行的自动续接，以及默认预算与停止条件。
3. **D9** MCP Host 与插件生命周期（依赖 M3）。
4. **D10** 为用户级技能目录增加工作区之外的只读根。
5. 使用真实 API 密钥运行基准（会产生费用）。
